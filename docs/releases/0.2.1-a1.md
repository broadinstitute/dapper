# DAPPER 0.2.1-a1

This alpha adds two things: evidence that grounds in the exact bytes of a
result file, and a common, versioned `Collection` base with a new
`ResultCollection` for analysis results. Both are additive.
Every identifier minted under 0.2.0 is unchanged, and the identity profile
is still DAPPER-ID-1. It is a schema and tooling snapshot; there is no Python
package to install.

## Changes

- **`ValueLocator`** pins one serialized value inside a File: the byte span,
  the value as read (`value_text`), a readable selector and the media type. A
  verifier checks the File's sha256, then compares
  `file[byte_start : byte_start + byte_length]` with `value_text`.
- **`EvidenceItem.value_locators`** grounds evidence in result-file values.
  `source_claims` is now optional, so evidence read from a file needs no
  synthetic intermediate claim. Evidence with locators must name its
  `target_proposition` and give an `explanation`. `direction` stays optional
  unless `source_claims` is also present.
- **`Collection`** (abstract) is a `Set` whose members are other DAPPER
  records. It adds optional versioning: `collection_key`, shared across
  versions; `version`; and `was_revision_of`, which chains each version to the
  one before. `GeneSetCollection` now inherits from it, so gene-set libraries
  can be versioned too, and `ResultCollection` is new.
- **`ResultCollection`** is one immutable version of a named collection of
  analysis results. Its `members` are Datasets. It also lists the claim and
  query template Files and the manifest File it was built from, and records
  `methods` and the `dataset_dimensions` that identify each Dataset.
  `collection_key` and `version` are required. Claims do not reference the
  collection, so a new version re-addresses only the claims whose template or
  file changed.
- **`Dataset.dimension_values`** and **`Dataset.file_roles`** place a Dataset
  in its collection, e.g. `{trait: KPN.TRAIT:0000505, library: cfde-inc-v2}`
  with its `gene_stats` file. Both are inline value objects (`DimensionValue`,
  `FileRole`) that contribute to the Dataset's identity.
- **Linter.** A new `result-collection` profile. New checks that member
  Datasets give every dimension in order, that no two Datasets share all
  dimension values, that a `trait` dimension agrees with the `trait` slot,
  that role files are in `has_file`, and that `n_members` matches. For any
  Collection, `was_revision_of` must stay within one class and one
  `collection_key`. An earlier version in the same document counts as
  upstream (`prov:wasRevisionOf` is a derivation). The linter warns when a
  version lists more than one method, or when a member file came from a method
  it does not list.
- **Docs and examples.** A [result collections guide](../../schema/docs/result-collections.md),
  including why mixing methods in one collection is usually an anti-pattern,
  and a [Croissant guide](../../schema/docs/croissant.md) for importing
  [Croissant](https://mlcommons.org/working-groups/data/croissant/) records
  into DAPPER and publishing DAPPER results as Croissant, using existing
  classes only. Its worked example is a Croissant 1.0 record that `mlcroissant`
  loads. A test checks every `FileObject` against the matching DAPPER `File`
  by sha256.
  Two synthetic examples whose NDJSON result files are real bytes, so their
  locators are verified in tests. The portal shows both.

## Migration from 0.2.0

- No identifiers change. The new Dataset and Collection slots hash only
  when present, and the frozen DAPPER-ID-1 vectors still reproduce.
  `GeneSetCollection` moved from `is_a: Set` to `is_a: Collection`, which is
  itself a Set, so it keeps every slot it had.
- Documents that minted ValueLocators against the uncommitted proposal (group
  key `value_locators`) are valid as written. The class, its fields and their
  hashability are unchanged.
- Evidence that grounds only in `value_locators` must have
  `target_proposition` and `explanation`. Re-mint after adding a missing
  explanation, since it is a hashed field.
- `ResultCollection` and `GeneSetCollection` are siblings. A gene-set library
  stays a `GeneSetCollection`. When results are sliced by library, the library
  is a result-collection dimension.
- The `collection` alias moved from `Set` to `Collection`.

## Pull and validate

```sh
git clone --branch 0.2.1-a1 https://github.com/broadinstitute/dapper.git
cd dapper
uv run schema/lint/lint_provenance.py \
  schema/examples/example_result_collection.yaml --strict
uv run --with-requirements tests/requirements.txt pytest tests/ -q
```

The pre-commit hooks (`prek run`: `linkml-lint` with no warnings, then the
full test suite) pass. Run with `--with-requirements tests/requirements.txt`,
`test_model_uris.py::test_imported_type_native_links_resolve_after_documentation_merge`
fails, on 0.2.0 too. It checks how the LinkML documentation generator merges
imported types, and it does not affect the schema or identifiers.
