# DAPPER 0.2.0-a1

This alpha packages gene-set libraries and GMT row references alongside scientific
accounts, claims, evidence, and citations. It is a schema and tooling snapshot;
there is no Python package to install.

## Changes

- Model libraries as `GeneSetCollection`, with individual `GeneSet` members,
  reciprocal membership links, distinct-gene counts, and pointers into GMT files.
  Generic inputs and intermediates use `File`; C2M2 metadata remains on `C2M2File`.
- Declare document-local prefixes, reject unresolved namespaces, and export
  full-URI documents with consistent content-derived identifiers.
- Include a real HuBMAP example with 358 sets and 964 distinct source gene symbols.
  Every compact YAML `gmt_entry` matches its GeneSet ID and the corresponding
  row in `genesets.dapper-ids.gmt`; both file representations have verified checksums.
- Separate propositions from attributed claims and typed scores. Organize
  questions, knowledge gaps, hypothesis roles, context, claims, and conclusions
  in `ScientificAccount`, with optional `MechanisticModel` structure and saved
  `Paragraph` text.
- Validate evidence relationships, scientific-account structure, and paragraph
  citation spans. A separate revisioned citation metadata contract preserves
  scientific identity. Update the portal and generated model documentation.

## Migration from 0.2.0-a0

- Use `gene_set_collections` for GMT libraries; each `gene_sets` record describes
  one set. Put paths in `location`, source labels in `alternate_identifier`, and
  readable labels in `name`. `has_gmt_file` references a local minted File record.
- `in_gmt_file` and `gmt_entry` are representation metadata excluded from a
  GeneSet's hash. Mint the sets, serialize their IDs into the GMT, calculate its
  checksums, then mint the File and collection. Re-mint earlier records and all
  dependent references under this schema; do not mix alphas when verifying IDs.
- `in_gene_set_collection` is an unhashable inverse link; collection `members`
  and `has_gmt_file` remain hashable. A full-URI export may have different
  GeneSet IDs, but retains literal `gmt_entry` values that select the same GMT rows.
- Replace legacy `Hypothesis` records with a Proposition in an account's
  hypothesis role. Replace `CompositeClaim` containers with ScientificAccounts;
  use a separate Claim when making an attributed concluding assessment.
  Mechanistic structure belongs in `MechanisticModel`.

## Pull and validate

```sh
git clone --branch 0.2.0-a1 https://github.com/broadinstitute/dapper.git
cd dapper
gh release download 0.2.0-a1 --repo broadinstitute/dapper \
  --pattern 'geneset-hubmap-0.2.0-a1.zip'
unzip geneset-hubmap-0.2.0-a1.zip
uv run schema/lint/lint_provenance.py \
  geneset-hubmap-0.2.0-a1/geneset.provenance.corrected.yaml --strict
uv run schema/lint/lint_provenance.py \
  geneset-hubmap-0.2.0-a1/geneset.provenance.expanded.yaml --strict
```

The bundle includes the compact and full-URI YAML documents, original and
DAPPER-ID GMT files, a README, and a manifest pinning the release commit and
file checksums. `export:` points to the tagged GMT asset on GitHub; `humgen:`
retains the original `file:///humgen/` source locations. No source files need
to be fetched to run structural and identity validation.

The linter does not download GMT files; regression tests check every row and
checksum in the bundled example. Other source file contents and execution
records remain source-reported. Gene symbols are preserved without alias
normalization. Citation registry persistence and DOI/resolver services remain
application responsibilities.

Build the portal and model navigator with `uv run tools/build_docs.py --serve`.
The hosted Pages site follows `main`; the release tag pins this alpha independently.
