# DAPPER 0.2.0-a2

This alpha adds vector embeddings as first-class, content-addressed records
that any node can carry. It is additive: no identifier minted under 0.2.0-a1
changes.

## Changes

- New `Embedding` class (`embeddings:` group): a model-computed vector
  representing another node (`embedding_of`), with model, provider,
  dimensions, dtype, normalization, the embedded text and its template, a
  `vector_sha256` of the stored bytes, and the generating Activity. Vectors are
  not inlined; `has_vector_file` plus `vector_row` locate a row of a shared
  matrix `File` and are unhashable, mirroring `GeneSet.in_gmt_file` + `gmt_entry`.
- New unhashable `has_embedding` slot on `Node` (the inverse of
  `embedding_of`) and a `HasEmbedding` edge class, so embedding a node never
  changes the node's identifier.
- New enums `EmbeddingDtypeEnum` and `EmbeddingNormalizationEnum`.
- Linter: `Embedding` may be the subject of `WasGeneratedBy`; `HasEmbedding`
  edges accept any `Node` subject. Embedded nodes remain terminal results.
- Portal and model documentation include the new class, links and an
  [embeddings guide](../../schema/docs/embeddings.md) with a
  [minted example](../../schema/examples/example_embedding_graph.yaml).

## Migration from 0.2.0-a1

- Nothing to re-mint. Existing documents validate unchanged; `has_embedding`
  is optional and unhashable.
- To add embeddings to an existing document: mint the matrix File, the
  Activity and the Embedding records, then set `has_embedding` on the embedded
  nodes and (optionally) reify `has_embedding_edges`. Do not add a `prov:used`
  edge from the embedding Activity to the embedded nodes; point it at the data
  the texts came from.

## Pull and validate

```sh
git clone --branch 0.2.0-a2 https://github.com/broadinstitute/dapper.git
cd dapper
uv run schema/lint/lint_provenance.py \
  schema/examples/example_embedding_graph.yaml --strict
uv run schema/identity/dapper_identity.py verify \
  schema/examples/example_embedding_graph.yaml
```
