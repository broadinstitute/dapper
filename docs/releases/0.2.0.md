# DAPPER 0.2.0

This release consolidates the 0.2.0 alphas: a generic `File` model and
provenance linter (0.2.0-a0), gene-set libraries with GMT row references and
scientific accounts, claims, evidence, and citations (0.2.0-a1), and vector
embeddings as content-addressed records any node can carry. It is a schema and
tooling snapshot; there is no Python package to install.

## Changes

### Files, identifiers, and linting (from 0.2.0-a0)

- Add a generic `File` model and searchable schema documentation.
- Correct ID assignment and stop silent data loss when minting.
- Add a provenance-graph linter that validates complete provenance records,
  terminal relationships, and that every edge connects two nodes.

### Gene-set collections and scientific provenance (from 0.2.0-a1)

- Model libraries as `GeneSetCollection`, with individual `GeneSet` members,
  reciprocal membership links, distinct-gene counts, and pointers into GMT files.
  Generic inputs and intermediates use `File`; C2M2 metadata remains on `C2M2File`.
- Declare document-local prefixes, reject unresolved namespaces, and export
  full-URI documents with consistent content-derived identifiers.
- Include a real HuBMAP example with 358 sets and 964 distinct source gene symbols.
  Every compact YAML `gmt_entry` matches its GeneSet ID and the corresponding
  row in `genesets.dapper-ids.gmt`; both file representations have verified checksums.
- Separate propositions from attributed claims and typed scores. Organize
  questions, knowledge gaps, hypothesis roles, context, claims, and conclusions
  in `ScientificAccount`, with optional `MechanisticModel` structure and saved
  `Paragraph` text.
- Validate evidence relationships, scientific-account structure, and paragraph
  citation spans. A separate revisioned citation metadata contract preserves
  scientific identity. Update the portal and generated model documentation.

### Embeddings (new since 0.2.0-a1)

- New `Embedding` class (`embeddings:` group): a model-computed vector
  representing another node (`embedding_of`), with model, provider,
  dimensions, dtype, normalization, the embedded text and its template, a
  `vector_sha256` of the stored bytes, and the generating Activity. Vectors are
  not inlined; `has_vector_file` plus `vector_row` locate a row of a shared
  matrix `File` and are unhashable, mirroring `GeneSet.in_gmt_file` + `gmt_entry`.
- New unhashable `has_embedding` slot on `Node` (the inverse of
  `embedding_of`) and a `HasEmbedding` edge class, so embedding a node never
  changes the node's identifier.
- New enums `EmbeddingDtypeEnum` and `EmbeddingNormalizationEnum`.
- Linter: `Embedding` may be the subject of `WasGeneratedBy`; `HasEmbedding`
  edges accept any `Node` subject. Embedded nodes remain terminal results.
- Portal and model documentation include the new class, links and an
  [embeddings guide](../../schema/docs/embeddings.md) with a
  [minted example](../../schema/examples/example_embedding_graph.yaml).

## Migration

### From 0.2.0-a1

- Nothing to re-mint. Identifiers minted under 0.2.0-a1 are unchanged, and
  existing documents validate unchanged; `has_embedding` is optional and
  unhashable.
- To add embeddings to an existing document: mint the matrix File, the
  Activity and the Embedding records, then set `has_embedding` on the embedded
  nodes and (optionally) reify `has_embedding_edges`. Do not add a `prov:used`
  edge from the embedding Activity to the embedded nodes; point it at the data
  the texts came from.

### From 0.2.0-a0 or 0.1.0

- Use `gene_set_collections` for GMT libraries; each `gene_sets` record describes
  one set. Put paths in `location`, source labels in `alternate_identifier`, and
  readable labels in `name`. `has_gmt_file` references a local minted File record.
- `in_gmt_file` and `gmt_entry` are representation metadata excluded from a
  GeneSet's hash. Mint the sets, serialize their IDs into the GMT, calculate its
  checksums, then mint the File and collection. Re-mint earlier records and all
  dependent references under this schema; do not mix releases when verifying IDs.
- `in_gene_set_collection` is an unhashable inverse link; collection `members`
  and `has_gmt_file` remain hashable. A full-URI export may have different
  GeneSet IDs, but retains literal `gmt_entry` values that select the same GMT rows.
- Replace legacy `Hypothesis` records with a Proposition in an account's
  hypothesis role. Replace `CompositeClaim` containers with ScientificAccounts;
  use a separate Claim when making an attributed concluding assessment.
  Mechanistic structure belongs in `MechanisticModel`.

## Pull and validate

```sh
git clone --branch 0.2.0 https://github.com/broadinstitute/dapper.git
cd dapper
uv run schema/lint/lint_provenance.py \
  schema/examples/example_geneset_collection_rows.yaml --strict
uv run schema/lint/lint_provenance.py \
  schema/examples/example_scientific_account.yaml --strict
uv run schema/lint/lint_provenance.py \
  schema/examples/example_embedding_graph.yaml --strict
uv run schema/identity/dapper_identity.py verify \
  schema/examples/example_embedding_graph.yaml
```

For a separately supplied provenance document, run the linter from this tagged
checkout and pass the document's path. To generate a full-URI version, use
`uv run schema/expand_prefixes.py input.yaml --output expanded.yaml`.

The linter does not download GMT or embedding matrix files; regression tests
check the repository examples' row references and checksums. Other source file
contents and execution records remain source-reported. Gene symbols are
preserved without alias normalization. Citation registry persistence and
DOI/resolver services remain application responsibilities.

Build the portal and model navigator with `uv run tools/build_docs.py --serve`.
The hosted Pages site follows `main`; the release tag pins this version independently.
